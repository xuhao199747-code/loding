# 品牌诊断与 AI 底层支持能力改版设计

## 目标

将飞书项目文档中的“品牌诊断”和“AI 底层支持能力”整理为与 Agent 章节一致的表达体系，使每项能力都能回答四个问题：做什么、如何运行、由哪些技术组件构成、为什么采用这些组件。

## 内容依据

主要参考 Obsidian 知识库中的以下材料：

- `GEO/品牌诊断/品牌诊断-技术方案/全文.md`
- `GEO/品牌诊断/品牌诊断任务流程/全文.md`
- `GEO/品牌诊断/品牌诊断评分模型/全文.md`
- `GEO/数据与知识库/RAG架构设计/全文.md`
- `GEO/数据与知识库/LightRAG图谱构建方案/全文.md`
- `GEO/算法与模型/AlphaRank归因引擎/全文.md`
- `GEO/数据与知识库/向量检索技术架构/全文.md`

Obsidian 中标记为待确认、规划中或尚未上线的能力，不写成已经上线的事实。

## 统一版式

每个主要能力采用以下结构：

1. 一段产品化说明，解释它解决什么问题。
2. “运行逻辑”Mermaid 图，展示输入、处理和输出。
3. “采用的技术架构”Mermaid 图，展示组件与数据流。
4. 三列表格：`架构／技术 | 负责什么 | 为什么采用`。

表格遵循以下规则：

- 每个独立组件单独占一行，不使用“组件 A＋组件 B”合并解释。
- 名词统一使用 `English（中文解释）`。
- “负责什么”说明输入、处理和输出；“为什么采用”说明业务价值或工程取舍。
- 表述面向产品经理面试，保留必要技术深度，但不堆砌类名和实现细节。

## 第 11 章：品牌诊断

品牌诊断按 Main Agent（主智能体）任务链整理：

`品牌名／官网 → 品牌信息补全 → 竞品与 Prompt 生成 → 用户确认 → 多平台 AI 检索 → 诊断评分 → 结果聚合 → GEO 报告`

运行逻辑图展示草稿补全与正式诊断两个阶段；技术架构图展示 Main Agent、子智能体、检索工具、任务状态、并行执行、结果聚合和报告结构。

技术表至少拆分说明：

- Main Agent（主智能体）
- Brand Profile SubAgent（品牌资料子智能体）
- Prompt SubAgent（问题生成子智能体）
- AI Search Tool（AI 平台检索工具）
- Diagnosis SubAgent（诊断子智能体）
- Task State Machine（任务状态机）
- Parallel Execution（并行执行）
- Result Aggregator（结果聚合器）
- Report Schema（报告结构）
- Idempotency Control（幂等控制）

## 第 12 章：AI 底层支持能力

### 12.1 RAG 架构

作为总览，明确两条链路：

- 离线：数据采集、解析清洗、混合切片、元数据提取、向量化、索引与存储。
- 在线：Query 理解与改写、元数据过滤、关键词／向量／图谱多路召回、融合筛选、证据注入、大模型生成和引用回链。

### 12.2 LightRAG 图谱增强

解释 LightRAG 同时包含离线图谱建设和在线图谱查询。离线完成实体关系抽取、图谱合并、社区发现及多模态存储；在线支持 local、global、hybrid、mix、naive 和 community 查询。GraphRAG 社区模块用于补充宏观主题聚合与全局查询。

### 12.3 归因引擎

归因引擎是数据分析、诊断和策略之间的独立解释层，不归入 RAG。链路为：

`Metric 异常 → Factor 筛选 → Evidence Pack → Judge 评分 → 归因排序 → Action 映射 → Agent Context`

第一阶段明确采用 LLM／Skill Judge，不写成已经上线的机器学习或因果模型；后者仅作为演进方向。

### 12.4 混合召回

明确混合召回是在线检索策略：BM25 与 Vector 独立召回，先做项目、来源、粒度和时间过滤，再使用 RRF 完成排名融合，经过阈值、去重后返回 Top K 证据。图谱召回由 LightRAG 链路补充，不与 BM25／Vector 的 Hybrid 概念混淆。

### 12.5 向量检索基础设施

说明数据如何形成可检索能力：PG 保存事实数据，MaxCompute 全量与实时推送同步 OpenSearch；`text-embedding-v4` 生成 1024 维向量，OpenSearch 使用 HNSW 与 Cosine 完成近邻搜索，并用 `project_id` 等元数据保证租户隔离。

### 12.6 向量召回流程

说明一次在线请求如何执行：Query 改写、Query Embedding、元数据过滤、ANN 近邻搜索、相似度阈值、Top K、邻近 Chunk 扩窗和来源回链。与 12.5 的区别是：12.5 讲底层索引和存储，12.6 讲一次查询的运行过程。

## 关键事实修正

- 删除“归因引擎、混合召回都是 RAG 的一部分”的表述。归因引擎是独立分析层；混合召回属于 RAG 在线检索层。
- 删除“混合召回只有离线”的表述。混合召回发生在在线查询阶段。
- 保留“LightRAG 涉及离线和在线”，并分别解释图谱建设与图谱查询。
- Rerank（重排序）标记为预留能力，不写成当前上线组件。
- 行业知识爬取、OpenSearch 完整联调等仍按原始资料标记为规划或待跑通。

## 验收标准

- 第 11、12 章均不存在空标题或仅有一句话的能力章节。
- 所有架构图均使用 Mermaid，并能在飞书画板中正常渲染。
- 每张技术表严格为三列，独立组件不合并在同一行。
- 技术名词均附中文解释。
- 品牌诊断业务链、RAG 离线／在线边界、归因引擎边界及向量检索／向量召回区别表述一致。
- 原有 Agent 章节、评分体系和面试话术不修改。
