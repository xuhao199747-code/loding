# GEO 知识库分类重构设计

## 目标

将 Obsidian 主库 `/Users/mac/Documents/Obsidian/大威天龙/wiki/GEO` 中的 116 篇文章，从当前三个过宽的一级目录重构为 11 个面向产品能力的一级目录，使产品经理能够按业务问题快速定位资料，并将不必日常掌握的算法细节集中到技术选读区域。

## 保持不变的约束

- 一张原图仍对应一个独立文章目录。
- 每个文章目录根部仍只有 `全文.md` 和 `产品经理版.md`。
- 原图、OCR 和 SVG 继续保存在该文章的 `资源/` 中。
- 移动时以整个文章目录为单位，不拆分、不合并文章。
- 所有以 Agent 为主体的文章继续统一归入 `GEO 产品 Agent 方案`。
- `产品经理版.md` 继续保留，不因文章进入 `算法与模型` 而删除。
- 不改变原图、OCR、SVG、正文内容和文章名称。
- 不新增二级分类和分类索引文件。

## 归类优先级

遇到文章同时涉及多个主题时，按以下顺序判断：

1. 文章主体是 Agent 设计、Agent 运行或 Agent 协作，归入 `GEO 产品 Agent 方案`。
2. 文章主体是模型训练、算法计算或训练数据构造，归入 `算法与模型`。
3. 文章主体围绕具体电商或行业业务问题，归入 `电商与行业场景`。
4. 文章主体是品牌或网页诊断产品，分别进入 `品牌诊断` 或 `网页诊断与 SEO`。
5. 独立讲评分口径、准出规则或通用指标体系，归入 `指标与评测`。
6. 其余文章按主要产品能力归入 Prompt、内容、数据、商业化或工程目录。

补充边界：

- 品牌诊断中的评分模型服务于完整品牌诊断产品，保留在 `品牌诊断`。
- 电商关键词聚类以电商业务场景为主，归入 `电商与行业场景`。
- 向量检索以知识资产的存储与召回为主，归入 `数据与知识库`。
- SEO 专用指标不拆到通用指标目录，保留在 `网页诊断与 SEO`。
- 算法目录是产品经理的技术选读区，但其中的产品经理版仍提供必要理解。

## 迁移方法

1. 迁移前验证 116 个文章目录、116 份全文、116 份产品经理版、116 份 OCR 和 116 张原图仍存在。
2. 为十个新分类建立一级目录。
3. 按映射表将文章目录整体移动到目标分类。
4. 对存在 frontmatter `category` 字段的全文，将字段更新为新的一级分类名；不新增无必要的元数据。
5. 删除迁移后为空的 `产品功能` 与 `工程与运维` 目录。
6. 重新验证资源路径、Obsidian 回链、SVG XML、表格、代码围栏、UTF-8 和原图字节一致性。

移动前若发现目标目录存在同名文章，停止该篇迁移并先检查内容，不覆盖现有文件。

## 验收标准

1. GEO 根目录仅有上述 11 个一级分类。
2. 文章总数仍为 116，且目标分类篇数与表格一致。
3. 每个文章目录根部仍只有两份 Markdown 和一个 `资源/` 目录。
4. 116 张库内原图与 `/Users/mac/Desktop/GEO图/` 中的来源逐字节一致。
5. 所有全文都能解析到本目录中的唯一原图。
6. 所有产品经理版都能回链到本目录全文。
7. 所有资源引用无断链，所有 SVG 可被 XML 解析且被正文引用。
8. Markdown 表格列数一致，代码围栏成对，文本编码有效。

10. 不改动文章正文语义，不新增与分类无关的内容。
