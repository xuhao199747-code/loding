# GEO 项目总览文档设计

## 目标

在 Obsidian 主库 `/Users/mac/Documents/Obsidian/大威天龙/wiki/GEO` 根目录创建 `GEO项目总览.md`，以产品闭环为主线，从行业变化讲到产品推进路线，帮助新接手项目的产品经理快速理解 GEO／AlphaRank 项目的完整逻辑，同时提供产品负责人做判断时需要的决策框架。

## 文档定位

- 文档类型：产品经理视角的项目总览、接手手册和知识库导航。
- 主要读者：AI 产品经理、项目负责人及需要快速理解 GEO 项目的协作角色。
- 阅读目标：回答“为什么做、为谁做、解决什么问题、产品如何运转、依赖哪些能力、如何判断有效、下一步怎样推进”。
- 存放位置：GEO 根目录，作为知识库入口，不归入任何图片文章分类。
- 文档数量：只创建 `GEO项目总览.md`，不创建“全文”和“产品经理版”两份。
- 文档不属于质量报告，也不改变一图一文文章目录。

## 组织主线

全文使用以下产品闭环串联：

```text
行业变化
→ 用户问题
→ 产品定位
→ 产品架构
→ 核心流程
→ Agent 执行
→ 数据知识
→ 算法指标
→ 内容发布
→ 效果回流
→ 商业化
→ 路线图
```

不按现有 11 个分类逐个罗列，而是在主线中引用相应分类下的材料。

## 章节结构

### 1. 项目一句话说明

用一段话说明 AlphaRank 面向 AI Search 场景，把监测、诊断、策略、内容执行和效果验证连接成持续优化闭环。

### 2. 行业变化

说明搜索入口从 Search Engine 向 Answer Engine 演进，以及 GEO 相比传统 SEO 新增的可见度、引用、品牌认知和推荐问题。

### 3. 用户问题

从品牌方和营销团队视角归纳机会发现、问题诊断、内容优化、效果验证、竞品判断和趋势预测等核心问题。

### 4. 产品定位

解释 AlphaRank 的目标用户、核心价值、产品边界，以及“数据—知识—Agent—应用”的价值链。

### 5. 产品价值闭环

用 Mermaid 绘制一张总闭环图：

```text
监测 → 发现 → 诊断 → 归因 → 策略 → 生成／优化 → 发布 → 验证 → 回流
```

图后逐段解释每一环的产品输入、输出和用户价值。

### 6. 产品整体架构

以应用层、Agent 层、知识层、数据层和外部服务说明系统分工。架构解释必须站在产品职责和能力边界角度，不展开不必要的底层实现细节。

### 7. 用户端核心流程

梳理品牌初始化、Prompt 构建、品牌诊断、网页诊断、策略制定、内容生成、发布验证和持续监控的端到端路径。

### 8. Agent 执行体系

说明统一入口、路由、Agent Team、Skill、Tool、Memory、Context、协议和评估闭环。重点解释不同 Agent 的职责、协作关系及人工介入位置。

### 9. 数据资产和知识体系

说明 AI Answer、Citation、网页、品牌、行业、Prompt、指标、Claim、Benchmark、向量检索和知识图谱如何沉淀为可复用资产。

### 10. 算法和指标体系

只保留产品经理必须掌握的算法输入、输出、阶段演进、离在线差异、置信度、评测方式和风险，不复述复杂公式。

### 11. 内容生产和发布

说明内容策划、生成、诊断、优化、审核、发布、渠道适配和内容资产回流的产品要求。

### 12. 效果验证和数据回流

连接 GEO 指标、业务指标、A/B 实验、归因、评估 Agent 和策略迭代，明确不能把相关性直接表述为因果。

### 13. 电商和行业场景

总结 Lazada、电商意图、行业品牌库和行业知识推荐等资料体现的行业优先、电商优先方向。

### 14. 商业模式

根据现有定价、成本、订阅和 API 资料，说明产品交付形态、成本组成和商业化依赖；原文未形成确定结论的部分标记“待确认”。

### 15. 当前建设状态

用“已有能力、建设中能力、待规划能力”三个状态整理当前进展。状态必须能从现有材料回溯，不根据文件日期自行推断最新进展。

### 16. 产品风险

整理数据波动、平台依赖、指标口径、归因可信度、内容质量、发布渠道、知识更新、权限安全和成本等产品风险。

### 17. 产品经理决策清单

形成接手项目时需要确认的问题清单，覆盖目标用户、核心场景、北极星指标、数据可用性、Agent 成功率、内容准出、实验周期、发布边界、商业模型和版本优先级。

### 18. 产品推进路线图

按“底座统一—核心闭环—Agent 协作—行业落地—商业化扩展”的依赖关系说明推进顺序。路线图只重组现有文档中的方向，不自行承诺日期。

### 19. 知识库阅读导航

为不同阅读目的提供 Obsidian 回链：产品全貌、Agent、诊断、Prompt、内容、数据知识、算法、指标、电商、商业化及工程运维。

## 来源和回链规则

1. 事实、数字、指标、产品状态和方案结论只能来自现有 116 篇文章。
2. 每个章节至少链接一篇直接支撑该章节的文章；关键结论尽量在同段末尾添加回链。
3. 使用带路径的 Obsidian WikiLink，例如 `[[GEO 产品 Agent 方案/AlphaRank产品架构/全文|AlphaRank产品架构]]`。
4. 产品经理版可用于快速理解，但涉及数字、接口、字段或状态时回查同目录 `全文.md`。
5. 多篇资料存在不同口径时，同时列出差异并标记“待确认”，不自行选择一个结论冒充确定事实。
6. 不引用迁移前的旧标题或旧分类路径。

## 写作规则

- 先写产品结论，再解释技术依据。
- 英文概念首次出现时补充中文解释。
- 不使用空泛宣传语，不增加现有资料没有的行业数据或竞品结论。
- 技术内容聚焦产品输入、输出、依赖、边界、风险和验收方法。
- 文档允许使用表格、列表和一张 Mermaid 总闭环图；不复制各文章已有的复杂技术流程图。
- 不生成额外质量报告、图片、OCR 或 SVG。

## 验收标准

1. `GEO项目总览.md` 位于 GEO 根目录且可在 Obsidian 中直接打开。
2. 文档完整覆盖 19 个章节，并遵循产品闭环主线。
3. 文档包含一张可解析的 Mermaid 总闭环图。
4. 所有事实可回溯到现有文章，没有无来源的新产品事实。
5. 所有内部 WikiLink 均指向迁移后的真实文件，断链数为 0。
6. 所有明确冲突或信息缺口均标记“待确认”。
7. 英文核心概念均提供中文解释。
8. 文档不改变任何现有文章及资源文件。
9. 文档不是分类清单堆砌，能够从头到尾解释项目如何形成产品价值闭环。
