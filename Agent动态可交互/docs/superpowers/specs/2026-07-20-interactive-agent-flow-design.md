# Agent 动态可交互流程演示设计

## 1. 目标

将现有静态 Agent 架构图改造成暗色、中英双语、可逐步演示和自由探索的单页 HTML。界面需要同时满足技术方案讲解与产品流程演示，并为后续接入真实 Agent/API 保留数据与事件接口。

首版使用模拟运行数据，不调用真实模型、检索服务或外部工具。

## 2. 核心显示模型

界面采用“固定架构地图 + 局部聚焦放大 + 本次执行轨迹”的三层模型。

1. **全局架构层**：完整 Agent 架构保持稳定布局，表达系统有哪些模块及所有可能关系。
2. **运行轨迹层**：叠加本次运行实际经过的节点、分支、并行路径、回传和循环；不改变底层架构位置。
3. **当前事件层**：一次只解释一个执行事件，展示简短目的、输入、输出和状态；详细数据按需展开。

架构图在执行过程中不重新排版。进入复杂模块时，主画布平滑放大该模块；完整架构缩为右上角小地图，持续提供定位和模块切换。

## 3. 信息架构

### 3.1 全局模块

首版包含五个核心区域：

1. 输入与编排（Input & Orchestration）
2. Agent 核心（Agent Core：Orchestrator、LLM、Planning、Memory）
3. 检索增强生成（RAG Augmentation）
4. 工具执行与反馈（Tools, Action & Feedback）
5. 最终响应（Final Response）

Guardrails（权限、安全、评估、审计）作为持续生效的横切能力层，不进入普通步骤序列。

### 3.2 三级导航

- **系统层**：查看完整架构。
- **模块层**：聚焦某个模块的内部结构。
- **节点层**：查看节点的输入、输出、状态、条件和回传目标。

主画布左上角显示面包屑，例如：

`Agent 系统 > RAG 检索增强 > 检索路由`

## 4. 右上角小地图

小地图固定在主画布右上角，既承担定位，也作为模块入口。

小地图显示：

- 完整架构缩略图。
- 当前聚焦模块和当前执行节点。
- 主画布当前可视范围。
- 已完成路径、本次实际路径和回传方向。
- 可点击模块；点击后主画布聚焦对应模块。

小地图旁提供三个控制：

- 全局视图（Overview）
- 跟随执行（Follow Run）
- 回到当前节点（Return to Live）

切换视图只改变镜头，不改变 Agent 执行状态、分支选择或运行历史。切回全局视图时自动暂停播放，避免错过执行过程。

## 5. 运行关系与交互语义

执行轨迹不能建模为单一线性步骤。首版支持以下关系：

| 类型 | 语义 | 显示方式 |
| --- | --- | --- |
| 顺序 | A 完成后执行 B | 单向实线与流动高亮 |
| 决策 | 根据条件选择路径 | 决策节点及可点击选项 |
| 并行 | 多条路径同时执行 | 多条路径同时点亮并显示独立状态 |
| 汇聚 | 等待有效分支后合并 | 多路进入同一汇聚节点 |
| 回传 | 结果返回上游模块 | 反向动画并同时高亮来源与目标 |
| 重试 | 重新执行同一节点 | 节点轮次递增并保留上次记录 |
| 重规划 | 返回 Planning 生成新路径 | 返回 Planning 的反馈连线 |
| 整体模块 | 一个事件代表完整子系统 | 聚焦后展开模块内部节点 |

决策事件不能直接使用固定“下一步”。控制文案根据状态变化为“选择路径”“启动并行检索”“执行回传”“重新规划”等。

## 6. 典型流程

### 6.1 开场

1. 完整架构淡入并停留 3–5 秒。
2. 标出五个核心区域，不逐个解释内部节点。
3. 架构缩为右上角小地图。
4. 主画布聚焦“用户任务进入”，开始运行演示。

### 6.2 RAG 示例

1. Agent 核心判断需要补充资料。
2. 主画布聚焦 RAG，显示查询处理。
3. 路由节点提供“仅向量检索、仅联网搜索、双路并行”。
4. 未选分支弱化；并行模式同时显示两路进度。
5. 有效分支完成后进入合并、去重和重排序。
6. 上下文组装作为完整子模块展开。
7. 增强上下文回传 LLM/Orchestrator。

### 6.3 工具与反馈示例

1. Agent 核心选择工具能力。
2. 权限与人工确认决定是否执行。
3. Action 子模块执行有副作用的外部操作。
4. Observation 回传结果。
5. 评估节点选择完成、重试或重规划。
6. 循环显示轮次及返回目标。

## 7. 查看状态与执行状态

界面区分：

- 当前查看位置（Viewing）
- Agent 实际运行位置（Live）

用户通过小地图查看其他模块时，执行位置不随之改变。此时显示“回到当前执行”按钮。

“跟随执行”开启时，镜头自动聚焦当前节点；关闭或锁定视图后，Agent 不抢回镜头。

## 8. 播放与导航

固定控制区包含：

- 上一步
- 播放/暂停
- 下一事件或当前动作按钮
- 速度调节
- 重新开始
- 当前轮次和事件编号

历史节点点击默认只查看快照，不回退执行状态。需要从历史节点重新运行时，使用明确的“从此处重新运行”操作。

键盘支持：左右方向键切换、空格播放/暂停、Esc 返回上一级视图。

## 9. 状态系统

节点和分支至少支持：

- 等待（Waiting）
- 运行（Running）
- 成功（Success）
- 失败（Failed）
- 跳过（Skipped）
- 阻塞（Blocked）
- 重试（Retrying）
- 已取消（Cancelled）
- 部分完成（Partially Complete）

并行汇聚节点必须记录等待分支数；反馈循环记录轮次和返回原因。

## 10. 视觉规范

采用克制的技术暗色，不使用白色页面或大面积强霓虹。

| 用途 | 色值 |
| --- | --- |
| 页面背景 | `#050B14` |
| 画布背景 | `#081423` |
| 模块卡片 | `#0D1B2D` |
| 普通边框 | `#1E3855` |
| 当前节点 | `#38D1FF` |
| 已完成路径 | `#54D6AD` |
| 分支选择 | `#A88BFA` |
| 等待/警告 | `#FFBD59` |
| 错误/阻塞 | `#FF6978` |

中文是主信息，英文使用更小字号和更低对比度作为辅助。网格、非当前连线和未执行分支保持低亮度。发光仅用于当前节点、当前连线和回传动画。

## 11. 动画原则

- 镜头移动用于表达同一张架构图中的定位变化。
- 数据流动用于表达输入输出传递。
- 节点脉冲用于表达正在执行。
- 多线同时流动用于表达并行。
- 反向流动用于表达回传。
- 未选择路径不消失，只弱化。
- 尊重 `prefers-reduced-motion`，提供关闭动画选项。

## 12. 数据与组件边界

首版使用数据驱动结构：

- `ArchitectureGraph`：模块、节点和静态关系。
- `ExecutionEvent`：本次运行发生的事件。
- `RunStateMachine`：决策、并行、汇聚、回传和重试规则。
- `TraceStore`：事件历史、轮次、输入输出快照。
- `GraphViewport`：全局/模块/节点三级镜头。
- `MiniMap`：定位、模块切换和实时位置。
- `Inspector`：按需展示节点详情。
- `PlaybackControls`：运行控制与历史查看。

模块之间通过稳定数据接口通信，视图切换不得修改运行状态。

## 13. 错误与安全

首版模拟以下异常：检索无结果、工具超时、权限不足和评估不通过。界面明确展示重试、重规划或请求人工确认。

工具执行展示是否有副作用、是否可重试、是否可撤销和幂等标识。Memory 区分运行状态、短期记忆、长期记忆和审计日志。

界面只展示决策摘要和依据，不展示隐藏思维链。

## 14. 响应式与可访问性

- 宽屏使用主画布与右上角小地图。
- 窄屏小地图可折叠，但“全局视图”和“回到当前节点”始终可用。
- 所有交互支持键盘操作与可见焦点。
- 状态不只依赖颜色，同时使用图标和文字。
- 中英文长文本不得挤压节点或覆盖连线。

## 15. 首版范围

首版交付一个可直接打开的 HTML 原型，包含：

- 暗色完整架构总览。
- 全局、模块和节点三级视图。
- 右上角可交互小地图。
- 模拟输入、Agent 核心、RAG、工具反馈和最终响应流程。
- 决策、并行、汇聚、回传、重试和整体模块事件。
- 播放控制、查看/执行位置区分和运行轨迹。
- 中英双语与响应式布局。

不包含真实模型、真实检索、真实外部工具、用户账户或持久化后端。

## 16. 验收标准

- 用户无需阅读说明即可区分完整架构、本次路径和当前事件。
- 在任意聚焦层级都能通过右上角小地图定位并切换模块。
- 查看其他模块不会改变实际运行位置。
- 分支、并行、汇聚和回传使用不同且准确的视觉语义。
- RAG 结果明确回传 Agent 核心，不直接成为最终响应。
- Guardrails 明确表现为横切能力层。
- 上一步、播放/暂停和当前动作在常用窗口尺寸中可访问。
- 页面采用暗色技术风格，中文主信息和英文辅助信息层级清晰。
