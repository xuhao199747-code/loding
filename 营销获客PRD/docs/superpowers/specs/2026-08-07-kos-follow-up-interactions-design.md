# KOS 旅游流程后续交互设计

## 目标

让首页“游客经营 5 阶段”从展示型看板变成可进入、可推进的操作入口，同时保留现有旅游业务内容和规划信息。

## 交互方案

采用单文件内的轻量事件联动，不新增后端：

1. 点击五个流程阶段卡片，跳转到监控视图，并按阶段筛选客户。
2. 点击客户卡片，打开对应对话详情。
3. 在对话中点击“确认意向”“确认成交”“立即接手”等现有操作按钮，更新客户阶段、标签和待办提示。
4. 操作完成后回到流程看板时，同步刷新阶段人数和今日机会提示。
5. 对没有真实动作的展示区域不新增伪按钮；原有规划内容保留，仅作为辅助说明。

## 状态流转

`首次咨询 → 需求确认 → 方案报价 → 预订支付 → 出行服务`

每个客户保留现有数据结构，通过 `data-stage`/客户 id 关联阶段卡片、客户列表和对话场景。没有后端时使用页面内存状态，刷新页面后恢复演示初始数据。

## 兼容与验证

- 保持现有页面结构、旅游文案、响应式样式和无蓝框视觉调整。
- 优先复用现有按钮、对话场景和 `postMessage` 路由，不重写业务模板。
- 验证五个阶段均可点击、客户可进入对话、至少三类推进操作能更新界面，且所有内嵌脚本可编译。
