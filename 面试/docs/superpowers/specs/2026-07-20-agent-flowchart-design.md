# Agent 流程图优化设计

## 目标

基于用户提供的当前流程图，重新表达一个适合技术方案文档的 Agent 架构。图中同时呈现：

1. 用户请求从进入系统到最终输出的运行流程。
2. Agent 内部模块的职责、依赖关系与数据流。

不参考或复用之前版本的布局和结构。

## 设计方案

采用“上下两层架构”：

### 上层：运行流程

从左到右或从上到下表达主链路：

`用户输入（User Input） → Agent 编排器（Agent Orchestrator） → 任务分析与规划（Planning） → 工具选择与调用（Tool Use） → 动作执行（Action） → 最终输出（Final Response）`

编排器负责接收请求、协调各模块和控制循环；规划模块负责拆解任务与确定执行步骤；工具调用负责选择并调用外部能力；动作模块负责执行具体操作；最终输出负责汇总并返回结果。

### 下层：Agent 内部能力

将下列模块作为主流程的支撑能力，而不是并列的终点：

- 大语言模型（LLM）：理解请求、生成计划、进行决策。
- 思维链推理（COT）：支持复杂任务的分步推理。
- 检索增强生成（RAG）：从知识库或外部资料获取上下文。
- 记忆模块（Memory）：保存短期上下文和长期偏好/事实。
- 知识库（Knowledge Base）：为 RAG 提供可检索内容。

下层模块通过带标签的连接线向编排器、规划器或工具调用提供上下文；避免把 COT、RAG、Memory 误画成与 Action 同级的执行结果。

## 视觉与标注

- 使用中英双语节点名称，例如“任务规划（Planning）”。
- 主流程使用高对比度实线箭头。
- 支撑能力使用较弱颜色或虚线连接，表示辅助关系。
- 输入、处理、工具、知识、输出使用不同但克制的颜色分组。
- 所有箭头保持单向、避免交叉；需要循环时使用明确的“反馈/继续执行”回路。
- 增加图例，解释主流程线、辅助关系线和反馈回路。

## 验收标准

- 读者可以不看说明文字，识别主流程的起点、决策、执行和输出。
- 能区分“模块职责”和“运行先后”。
- `Planning` 已纳入主流程，`Tool Use` 不再反向指向 LLM 造成歧义。
- `COT`、`RAG`、`Memory`、`Knowledge Base` 有明确的输入/输出关系。
- 图中不出现孤立节点、无意义的交叉连线或未解释的回路。
- 标签统一为中英双语，适合技术方案文档阅读。
